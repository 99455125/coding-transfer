# Every Sync：可靠加密传输设计

## 目标与边界

把当前人工逐块复制粘贴升级为人工生成、人工开始的自动传输。发送方完成包后点“发送”；接收方主动点“接收”或“接收并应用”后，双方通过剪贴板交换密文帧并自动重试/补块。监听只在一次已启动的传输期间存在，后台任务有界，不阻塞 IDEA EDT。一次仅允许一个项目会话；同时发送时明确提示并拒绝第二个会话。

本改造不自动生成包、不监听保存、不引入任务队列、不重构项目数据为流式协议、不引入证书/签名/握手鉴权/额外防重放机制、不改造 Git 同步规则。既有 V2 Bundle/ACK、V3 WORKTREE、独立文件协议作为加密帧内层保留，完整包体校验、排除校验、stale 检查、锁、备份和回滚均保留。Java 21，不新增依赖。

## 身份、密钥和帧格式

两端由操作者配置同一随机识别串及独立共享密钥。识别串可用于剪贴板筛选，不是认证凭据；每端的密钥通过 IDEA PasswordSafe 按工作区身份保存，不进入 `config.yaml`、协议明文头或日志。设置界面提供生成安全随机值、复制/粘贴配置的能力，密钥不得自动跨设备同步。

外层剪贴板文本固定为 `<identity> <base64(nonce || AES-GCM(internal-version || message) || tag)>`。识别串仅用于定位正确通道；外层不暴露独立传输协议版本。帧版本、会话 UUID、消息方向、控制消息、块号/总数、块内容和所有回执均位于 AES-GCM 密文中。AAD 固定绑定协议域和识别串。每次新建帧使用 CSPRNG 产生 96-bit nonce；帧一旦生成，重传必须复用完全相同的密文。收到帧先比对本机识别串，再做 GCM 验证，错误密钥/损坏数据不写入持久状态。

内层项目数据块仍使用现有项目块编码与 SHA-256，普通文件仍使用其独立二进制块与 SHA-256；不得以 GCM 校验替代现有校验。分块默认 128 KiB，自动传输在帧层封装现有块文本。加密实现提供明确的编码/解码边界，单测验证篡改拒绝、错误密钥拒绝、帧字段保密、nonce 唯一，以及同一密文重传。

## 会话与可靠性

每次传输使用 UUID、端点角色、传输类型、项目/文件会话、内层块清单摘要和密钥配置身份。发送方先点击发送并发布 INVITE；随后接收方点击接收，读取已有 INVITE 并发布 READY；发送端收到 READY 后才开始传块。接收端每块校验后先调用既有项目/文件 inbox 原子持久化，再回 ACK；发送端只在收到该块 ACK 后推进。停等窗口为 1；有限超时重试，收到缺块列表/首缺块提示时补传。相同会话、方向和块号的相同密文幂等；冲突内容拒绝。重启后从持久化小型状态、当前未确认密文帧和内层 inbox 恢复；不在新传输层复制完整收件块或保存所有历史密文帧。接收中的新会话不得静默替换待处理内容。

自动监听在发送/接收动作启动时创建，在结束、取消、面板关闭或项目切换时停止。IDE 进程内由共享应用级协调器拥有唯一活动剪贴板租约，防止多个面板争抢。显式开始可发布首个 INVITE；活跃期间可以用合法的本会话对端帧替换当前剪贴板帧。若发现新普通剪贴板内容则暂停传输并提示，不覆盖；结束时仅当剪贴板仍是本会话帧才尽力清空。从不保存或恢复任意先前剪贴板内容。工作在线程池上执行，线程数、队列和轮询间隔有限；所有 UI 更新经 IDEA EDT。

## 两个项目方向的完成状态

### HOST → VM

HOST 人工生成工作树包，点发送后锁定该包和项目，VM 点接收。VM 收齐后完整校验 V3 包并将待处理内容可靠落盘，写入小型完成记录，然后发送 RECEIVED。HOST 收到后完成并释放该包的整包内存和本次发送缓存；丢失 RECEIVED 时可通过重复确认恢复。VM 释放传输缓冲，但保留待处理包供本地差异预览、原生 Diff/Merge 与人工应用。此后的本地预览/冲突解决/应用无 HOST 回执，不等待 HOST 确认，也不改 VM HEAD/index；取消冲突解决不写业务文件。

### VM → HOST

VM 人工生成 V2 SNAPSHOT/DELTA 并发送，HOST 点“接收并应用”，该动作授权应用。收齐并校验后继续走现有受控 HOST 导入事务。失败不产生成功 ACK。应用与基线持久化成功后，HOST 发送与现有协议同语义的业务 ACK；VM 只接受匹配当前 exact pending 的 ACK，持久推进整个 refs 基线后发 FINAL。HOST 持久确认 FINAL 并回复 FINAL_ACK；两端据此收敛到完成状态并释放本次传输缓存。若 FINAL 或 FINAL_ACK 丢失，接收方对重复 ACK/FINAL 依据有限完成记录回复，不重复覆盖文件或推进基线；UI显示“待确认”直至重传收敛。不得把分块确认或收齐确认当作业务 ACK/基线推进。无法保证网络故障下双方无限期断连时都知道对端已完成。

HOST 成功应用后保留小型 ACK/会话完成记录，直到 VM 最终确认或达到有界保留期；不删除 pending ACK、基线、备份。VM 发送 FINAL 后在有界宽限期继续重试，等 HOST 返回 FINAL_ACK；HOST 以小型完成记录响应重复 FINAL，不重复应用。达到宽限期仍未收敛时两端释放大对象并停止自动监听，保留显示为“待确认”；用户可显式继续确认以重新启动短期监听和重试。不得声称宽限期后仍可无限自动恢复。完成/取消/关闭释放大数组、字符串、预览、文件流和任务。失败时只保留续传所需缓存。

## 界面与设置

保留顶层“项目传输 / 文件传输”。项目页只有固定项目选择、只读角色、设置，以及一套主内容区；移除发送/接收子页。主内容按准备发送、活动传输、VM 待处理等状态切换，按钮位置固定。HOST 初始动作是“生成变更”和“接收并应用”；VM 初始动作是“生成全量”“生成增量”“接收”，发送仅在存在已生成且未锁定的包时可用。VM→HOST 完成后恢复初始状态；有基线才启用增量。状态区显示阶段、已确认块数、重试和结果。块复制/读取、逐块翻页和手动回执退出主流程；分块大小在设置中配置。清理/诊断/本地记录进“更多”。VM 收到 HOST 包后在主面板列文件，点文件打开 IDEA 原生 Diff，冲突使用原生 Merge。

普通文件继续独立于 Git 和角色：发送方人工选择文件并生成，对端点接收；收齐后由接收者选择本地路径保存，保留覆盖目标检查，不接收远程路径、不自动执行。保存成功后双方确认。加密轮询复用可靠帧状态机，但文件内容/持久缓存与项目协议隔离。

## 关键实现单元

- 新增核心 `EncryptedFrameCodec`：AES-GCM、身份外层解析、认证数据和明文控制帧模型；无 IDEA 依赖。
- 新增核心 `TransferSessionStore` / `ReliableTransferEngine`：持久帧、传输状态、块 ACK/重试、幂等完成记录；只存小型状态，项目/文件内容使用现有收件箱。
- 扩展核心传输门面：现有项目/文件块仍可独立调用，自动层适配它们，不改变现有块编码。
- 新增 IDEA `TransferCoordinator`：基于有限轮询任务与剪贴板 API，控制租约、生命周期和 EDT 派发。
- 更新 Settings 保存公开识别串和 chunk size；密钥经 PasswordSafe 存取。协议参数不能落配置或日志。
- 重构 `SyncPanel` 为角色/状态驱动主区；`FileTransferPanel` 接入自动接收、确认和本地目标选择。
- 更新协议、架构、维护索引与 README；保留明确的项目数组峰值限制。

## 验收

焦点覆盖加密与篡改拒绝、nonce/密文复用、乱序/重复/缺块、超时重试、收件持久化先于确认、两种方向的不同完成语义、ACK 丢失恢复和幂等、exact pending 基线推进、剪贴板租约、任务释放/缓存边界、未解决冲突取消不写入、UI 状态动作。按 MAINTENANCE 先执行最小相关 transport/cache 检查；受影响的 bundle/worktree/core 分组按功能加入，不执行 `./build.sh test all`。真实双 IDEA/Windows 剪贴板/RDP 互操作需人工验收。测试 Git 写入仅限 disposable fixture。用户未要求打包或安装，不自动安装或外发。

## 实施风险

1. PasswordSafe API、插件服务生命周期和多面板全局协调必须符合 IC-251 SDK，避免后台监听泄漏或多个面板争抢。
2. 加密帧转义/剪贴板长度会增加体积，需明确帧上限并在过大时安全失败；不能假设剪贴板保留大块文本。
3. 最终确认丢失具有不可消除的不确定窗口，只能通过持久状态、重复响应和如实显示待确认收敛。
4. 项目包仍整体驻留内存，清理对象仅允许在生命周期结束后解除引用；不承诺 JVM RSS 立即下降。

## 需要负责人审阅的技术裁定

1. 识别串和共享密钥如何在两端初次交换：建议设置页“生成并复制配置串/在另一端粘贴”，配置串只在剪贴板短暂出现，密钥仍写入接收端 PasswordSafe 后立即不保留在普通配置中；是否接受这一配对路径？
2. 可靠协议初版建议单块停等（窗口=1），在 Windows 剪贴板和 RDP 延迟下更易做幂等/恢复；是否先接受吞吐量较低但边界简单的窗口？
3. 文件“保存成功后双方确认”建议定义为接收端原子保存后 ACK，发送端收到 ACK 后发送最终确认；无需任何 Git/角色语义。是否接受？
