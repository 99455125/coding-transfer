# 4.0 implementation plan / protocol amendment

Keep full snapshots and HOST→VM worktree deltas. Add full/incremental actual Git bundles VM→HOST. Each project has a single acknowledged receiver chain. First send full; HOST applies then copies ACK; VM accepts ACK before advancing its baseline. Pending generation alone never advances it. A different receiver, missing baseline, missing Git prerequisite or lost state requires full initialization.

Extend payload with snapshot UUID, parent UUID, VM branch, complete refs manifest and bundle bytes. DELTA file entries describe differences from the acknowledged snapshot; reconstruct the entire target from the saved pristine baseline, never from edited HOST files. Feed the reconstructed full target to existing authoritative preview/apply. This removes even local edits/additions outside delta entries, excluding configured exclusions and runtime metadata.

GitHistory: use fixed Git argument arrays, no shell/network/hooks. Package HEAD + all refs; exclude all acknowledged tips for incremental objects. No-new-object delta carries empty bundle plus refs and file changes. Validate/prerequisite-check/import into isolated staging first. HOST confirmation imports objects into a project-local .git (initialize if absent), mirrors VM branches under refs/remotes/vm-sync, tags under refs/tags/vm-sync, selects a dedicated local vm-work/<VM branch> (vm-work/detached when detached), and sets the index to VM HEAD without Git checkout touching worktree paths. Existing ordinary local branches are not deleted. Protect old HOST HEAD with a recovery ref; back up HEAD/index/ref state alongside file preimages. Ref updates are CAS transactions; on errors restore local metadata and files best-effort. No reset --hard, no git clean, no hooks, no outer Git operations.

BundleSync: retain pending full target on VM, acknowledged baseline on VM, accepted full target on HOST. Validate ACK against exact pending snapshot and parent. Persist pending/ACK under runtime .vmsync, never outer Git archives. Clipboard headers use VMSYNC/2 for extended metadata; 3.x file-only payloads remain readable but cannot initialize a Git increment chain. Both ends should upgrade.

UI: remove main role picker and its write listener. Settings is the sole role selection. Main header contains project and Settings. VM send actions: refresh list, generate full Bundle, generate incremental Bundle. HOST receive includes copy successful receipt; VM receives and explicitly confirms receipt. Confirm dialog states all local managed edits and staging are discarded and lists target HEAD/branch, actual directory and recovery behavior.

4.2 removes fixed transfer byte quotas; project payloads retain the existing in-memory schema and its representation/memory bounds. Full Git history contains historical/excluded files: workspace exclusions do NOT redact Git history. Only transfer trusted, authorized histories. No LFS media, submodule repositories, hooks/config, linked worktrees, shallow repositories or in-progress merge/rebase. HEAD's tree is validated for supported paths and file types. Runtime/Windows UI still needs real-machine acceptance.
